## 1. 使用的系统/方案

- **包管理器**: npm（通过 `package-lock.json` 锁定版本）。
- **构建工具**: Vite 5 (`vite: ^5.0.11`)，配合 `@vitejs/plugin-vue` 5、`vite-plugin-pages`、`vite-plugin-svg-icons`、`vite-plugin-top-level-await` 等插件。
- **语言与类型**: TypeScript ~5.3.0，使用 `vue-tsc --build --force` 做类型检查。
- **运行时依赖**: Vue 3.4.15、Vue Router 4.2.5、Pinia 2.1.7、Axios 1.6.7、Ant Design Vue 4.1.2、VueUse、Ramda、RxJS、i18n 等。
- **开发依赖**: ESLint 8 + Vue/TS 配置、Prettier 3、Husky 9 + lint-staged、Vitest 1、Tailwind CSS 3、Sass、MockJS 等。

项目根目录没有 `.npmrc`、`.yarnrc`、`pnpm-workspace.yaml` 或 `bun.lockfile`，也没有 `vendor/` 目录，说明未启用私有 registry、Yarn/Pnpm/Bun 工作区或源码 vendoring。所有第三方包均通过 npm 从镜像源安装并写入 `package-lock.json`。

## 2. 关键文件

- `package.json`：声明 `dependencies` / `devDependencies`、脚本命令（`dev`、`build`、`preview`、`test:unit`、`type-check`、`lint`、`format`、`prepare`）。
- `package-lock.json`：npm 生成的完整依赖树锁文件，其中 `resolved` 字段全部指向 `https://registry.npmmirror.com/...`，表明当前环境已把 npm registry 切换为淘宝镜像。
- `.gitignore`：忽略 `node_modules/`、`*.log`（含 yarn/pnpm debug/error log），不提交 `node_modules`。
- `.husky/pre-commit`、`.husky/commit-msg`、`scripts/verifyCommit.js`：在 Git 钩子中执行代码校验，间接约束依赖变更的提交质量。

## 3. 架构与约定

- **依赖分类**：运行时代码仅依赖 `dependencies` 中的包；构建、测试、格式化、类型检查工具放在 `devDependencies` 中，符合 npm 语义。
- **版本范围策略**：生产依赖普遍使用 `^` 前缀（如 `"vue": "^3.4.15"`、`"ant-design-vue": "^4.1.2"`），允许小版本自动升级；少数工具使用精确版本或波浪号（如 `"typescript": "~5.3.0"`、`"vite-plugin-svg-icons": "~2.0.1"`），以固定工具链行为。
- **锁定机制**：`package-lock.json` 由 npm 生成并提交到仓库，确保不同机器上安装出一致的依赖树。所有包的 `resolved` URL 统一走 `registry.npmmirror.com`，说明团队本地 npm 配置了该镜像。
- **无工作区/monorepo**：仓库是单项目结构，没有 workspace 或多包聚合配置。
- **无 vendoring**：没有将第三方库源码拷贝进仓库，也未见任何私有 npm registry 地址出现在源码中。

## 4. 约定与约束

- **描述性约定**：
  - 所有第三方依赖在 `package.json` 中以语义化版本范围声明，并由 `package-lock.json` 锁定具体解析结果。
  - 构建/测试/格式化相关工具一律放入 `devDependencies`。
  - `node_modules/` 被 `.gitignore` 排除，不纳入版本控制。
  - 提交前通过 Husky + lint-staged 对 `src/**/*.{js,ts,vue}` 执行 Prettier 格式化。
  - 提交信息通过 `scripts/verifyCommit.js` 进行校验（Git commit-msg hook）。
  - `prepare` 脚本调用 `husky install`，在首次 `npm install` 时自动安装 Git hooks。

- **可验证的规则**（来自仓库内明确存在的内容）：
  - `package.json` 中 `"private": true`，表示该包不应被发布到公共 npm registry。
  - `package.json` 中 `"type": "module"`，项目以 ESM 模式加载模块。
  - `package-lock.json` 中所有 `resolved` 字段均以 `https://registry.npmmirror.com/` 开头，反映当前 npm registry 已被替换为淘宝镜像。
  - `.gitignore` 显式忽略 `yarn-debug.log*`、`yarn-error.log*`、`pnpm-debug.log*`，但未见 `bun.lockfile` 或 `yarn.lock`，实际锁文件为 `package-lock.json`。
  - 脚本 `build` 使用 `run-p type-check "build-only {@}"` 并行执行类型检查与构建，`type-check` 使用 `vue-tsc --build --force`。

未发现以下机制：私有 npm registry 配置、`GOPRIVATE`（非 Go 项目）、`pnpm-workspace.yaml`、`yarn.lock`、`bun.lockfile`、源码 vendoring、依赖更新自动化脚本。
